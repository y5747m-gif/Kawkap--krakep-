# 🪐 كوكب كراكيب

> **عندك كراكيب؟ حوّلها لقيمة.**

منصة **Marketplace** بيئية يجتمع فيها البيع والشراء في مكان واحد — **العملاء هم البائعون والمشترون**، والمالك يدير المنصة مركزيًا ويستقبل جميع الطلبات عبر **WhatsApp** مع حفظها في لوحة إدارة كاملة.

---

## الفكرة والنموذج

```
العميل يفتح «اعرض شيئًا للبيع» — بدون تسجيل دخول (الحساب اختياري)
        ↓
يضيف الشيء الذي يريد بيعه (صور + مواصفات كاملة + سعر + موقع)
        ↓
ينشر الإعلان (فوريًا أو بعد مراجعة الإدارة)
        ↓
يظهر المنتج في الـ Marketplace والخريطة
        ↓
عميل آخر يشاهده ويطلبه
        ↓
إنشاء Order برقم فريد (KK-YYYYMMDD-NNNN) وحفظه في قاعدة البيانات
        ↓
تجهيز رسالة واتساب ديناميكية تلقائيًا وفتح واتساب على رقم المالك
        ↓
المالك يتابع الطلب ويحدّث حالته من لوحة الإدارة
```

- **ليس متجرًا تقليديًا**: المنتجات الأساسية يضيفها العملاء أنفسهم، لا الإدارة.
- **البيع بدون حساب**: تسجيل الدخول **اختياري وليس إجباريًا** — أي زائر ينشر إعلانه فورًا،
  ويُحفظ له رمز زائر (كوكي) يسمح له بتعديل أو حذف إعلانه من نفس المتصفح.
- **حساب واحد = مشترٍ + بائع** (لا حسابات منفصلة) — وفائدته متابعة الإعلانات والطلبات من أي جهاز.
- **الطلب يُحفظ في قاعدة البيانات أولًا دائمًا** ثم يُفتح واتساب — فلو أغلق العميل واتساب يظل الطلب موجودًا في النظام.
- **رقم واتساب المالك** (`01013178718` → `+201013178718`) لا يظهر في الواجهة العامة، ويُستخدم فقط داخل روابط WhatsApp، وموجود في **إعداد مركزي واحد** قابل للتعديل من لوحة الإدارة.

## المزايا

| المجال | التفاصيل |
|---|---|
| **البيع** | معالج 6 خطوات **بدون تسجيل دخول**: ماذا تبيع؟ → الصور (حتى 8 + كاميرا مباشرة) → **المواصفات الكاملة** → السعر والتفاصيل → الموقع (GPS + خريطة) → مراجعة الإعلان قبل النشر |
| **المواصفات** | الوزن + وحدته · النوع · الخامة · الماركة · الموديل · اللون · سنة الصنع · المقاسات · الحالة + **مواصفات إضافية حرة** (حتى 12 مواصفة: القدرة، السعة، هل يعمل؟ ... يكتبها البائع بنفسه) — كلها اختيارية وتظهر في صفحة الإعلان وفي رسالة واتساب |
| **بيانات التواصل** | اسم البائع ورقم التواصل **اختياريان** — بدون رقم يتابع المالك البائع من محادثة واتساب نفسها |
| **التسعير** | سعر ثابت · لكل كيلو · لكل قطعة · سعر للمجموعة · قابل للتفاوض |
| **التصنيفات** | 16 تصنيفًا (المعادن، النحاس، الحديد، الألومنيوم، البلاستيك، الكرتون، الورق، الإلكترونيات، الأجهزة الكهربائية، القديمة، الزيوت المستعملة، الأخشاب، قطع الغيار، أثاث، أدوات، أخرى) |
| **البحث** | في الاسم والوصف والتصنيف والموقع واسم البائع والمواصفات (الماركة/الموديل/النوع/الخامة) والكلمات المفتاحية + اقتراحات فورية |
| **الخريطة** | Map View بعلامة لكل منتج (السعر على العلامة) + تحديد موقع المنتج بالنقر + «كراكيب قريبة منك» بالمسافة التقريبية |
| **الطلبات** | طلب منتج مباشر أو سلة كاملة (تجميع تلقائي حسب البائع: طلب رئيسي + طلبات فرعية)، 9 حالات للطلب، خط زمني للتتبع |
| **واتساب** | رسالة طلب ديناميكية كاملة تُبنى من بيانات الطلب الفعلية → رابط `wa.me/201013178718` للمالك، وزر «فتح WhatsApp» للعميل من لوحة الإدارة |
| **لوحة البائع** | إعلاناتي (تعديل/إيقاف/حذف)، الطلبات على منتجاتي، إحصائيات (مشاهدات، طلبات، مبيعات، تقييم، الأكثر مشاهدة) |
| **الحساب** | بياناتي · أنا أبيع · طلباتي · المفضلة (مع تنبيه انخفاض السعر) · المحادثات · الإشعارات · الإعدادات |
| **لوحة الإدارة** | 12 مؤشرًا إحصائيًا، إدارة الطلبات (واتساب العميل + نسخ التفاصيل + تحديث الحالة)، إدارة المنتجات (قبول/رفض/إخفاء/تمييز/إيقاف/حذف)، المستخدمون، البلاغات، الإعدادات |
| **التقييمات** | 1–5 نجوم مع تعليق — **بعد إتمام الطلب فقط** ولطالب الطلب نفسه |
| **مقدمة الموقع** | Intro Animation: خلفية خضراء مرشوشة بالخردوات، الكوكب يظهر ويدور، وتنزل منه حروف «كوكب كراكيب» حرفًا حرفًا مع ومضة ضوئية — مرة واحدة لكل جلسة + زر تخطي + إعادة تشغيل من التذييل |
| **الحركة والإضاءة** | إضاءات محيطة متحركة، إضاءة تتبع المؤشر داخل البطاقات، لمعة مرور، ظهور تدريجي عند التمرير (Scroll Reveal)، انتقال ناعم بين الصفحات، كوكب يطفو في البطل — وكلها تتوقف تلقائيًا مع `prefers-reduced-motion` |
| **الأمان** | جلسات httpOnly، كلمات مرور bcrypt، تحقق من كل بيانات الطلب (منع الطلبات الوهمية)، الحسابات تُملأ من قاعدة البيانات فقط |

## الهوية البصرية

أخضر بيئي + تركوازي + أبيض + أخضر داكن مع لمسات ذهبية/برتقالية — Glass Cards، Soft Shadows، Gradients، Blur، Micro Animations، أيقونات SVG بالكامل (بدون Emojis في الواجهة)، خط Cairo، **Arabic RTL** و**Mobile First** مع Bottom Navigation وزر بيع مضيء في المنتصف.

**المقدمة والحركة:** عند أول زيارة في الجلسة تُفتح مقدمة بملء الشاشة — خلفية خضراء عميقة مرشوشة بالخردوات الطائرة (تروس، مفاتيح، أجهزة، كرتون...)، يظهر الكوكب ويدور بحلقته الذهبية وشهبه، ثم **تنزل حروف «كوكب كراكيب» من الكوكب حرفًا حرفًا** وتستقر مع توهج، ويظهر الشعار النصي وشريط التحميل ثم تنفتح الستارة على الموقع. الحروف العربية تبقى متصلة أثناء الحركة باستخدام ZWJ. يمكن التخطي بزر «تخطي المقدمة» أو بمفتاح Esc، وتُعاد من «شاهد مقدمة الكوكب» في التذييل أو بإضافة `?intro=1` للرابط.

## التقنيات

- **Next.js 16** (App Router) — Frontend + Backend في مشروع واحد
- **SQLite** عبر وحدة Node المدمجة `node:sqlite` (بدون أي خدمات خارجية) — قاعدة البيانات: `data/app.db`
- **Tailwind CSS** + خط **Cairo** ذاتي الاستضافة
- **Leaflet / OpenStreetMap** للخرائط (بدون API Keys)
- **bcryptjs** للمصادقة

> **متطلبات:** Node.js ≥ 22.13 — التطبيق يفحص الإصدار تلقائيًا قبل الإقلاع (`scripts/check-runtime.mjs`) ويوقف التشغيل برسالة واضحة إن كان الإصدار أقدم. استخدام إصدار أقدم يؤدي إلى ظهور **«500 Internal Server Error» على كل الصفحات** لأن وحدة `node:sqlite` غير متوفرة فيه.
>
> **Vercel:** نظام ملفات دوال Vercel للقراءة فقط، ولهذا كانت محاولة تفعيل SQLite/WAL على `data/app.db` تُسقط كل صفحات الإنتاج بخطأ 500 رغم نجاح البناء. يكتشف التطبيق Vercel الآن وينسخ قاعدة البداية إلى `/tmp` تلقائيًا عند الإقلاع، كما يمكن التحقق من الجاهزية عبر `/api/health`. هذا يُصلح الإقلاع والعرض، لكن `/tmp` **مؤقت وغير مشترك**؛ بيانات الحسابات والطلبات الجديدة ليست مضمونة بعد الـ cold start. للإنتاج الحقيقي استخدم استضافة Node بقرص دائم واضبط `KK_DB_PATH`، أو انقل قاعدة البيانات إلى خدمة مُدارة.
>
> إن ظهر الخطأ 500 خارج Vercel: تأكد من `node --version` ثم ثبّت Node 22.13+ من [nodejs.org](https://nodejs.org) أو نفّذ `nvm install 22 && nvm use 22` (يوجد ملف `.nvmrc`).

## التشغيل

```bash
npm install          # تثبيت الحزم
npm run db:seed      # زرع البيانات التجريبية (للتطوير فقط — يمسح البيانات الحالية)
npm run dev          # http://localhost:3000
```

```bash
npm run build && npm start   # نسخة الإنتاج
npm run db:reset             # إعادة تهيئة كاملة للبيانات التجريبية
```

| الحساب | الهاتف | كلمة المرور |
|---|---|---|
| **المالك / الإدارة** | `01013178718` | `Owner@2026` |
| مستخدم تجريبي (بائع + مشترٍ) | `01000000001` … `01000000005` | `Demo@1234` |

## واتساب — النقطة المركزية

**كل الطلبات تصل للمالك على واتساب تلقائيًا** — سواء كان العميل **يشتري** أو **يبيع**:

| الحالة | الزر | ما يحدث |
|---|---|---|
| شراء منتج / سلة | «إرسال الطلب» | حفظ الطلب في قاعدة البيانات برقم فريد → بناء رسالة منسّقة → فتح `wa.me/201013178718` فورًا |
| عرض شيء للبيع | «إرسال الطلب عبر واتساب» (آخر خطوة في معالج البيع) | حفظ الإعلان في قاعدة البيانات → بناء رسالة بكل تفاصيل المعروض → فتح واتساب المالك فورًا |
| استفسار / تواصل عام | زر واتساب العائم + زر «استفسار» | رسالة جاهزة على رقم المالك |

- الإعداد الوحيد للرقم: `OWNER_WHATSAPP_NUMBER` في جدول `admin_settings` (الافتراضي `01013178718`، ويُستخدم بالصيغة الدولية `+201013178718`) — قابل للتعديل من **/admin/settings**، ولا يظهر أبدًا في الواجهة.
- الرسائل **ديناميكية 100% ومنسّقة بإيموجيز** وعناوين عريضة وخطوط فاصلة: رقم الطلب/كود الإعلان، بيانات العميل أو البائع، المنتج والكمية والسعر والإجمالي، موقع الطرفين + **رابط خرائط جوجل**، طريقة الاستلام، الملاحظات، التاريخ، ورابط الإعلان والصورة.
- نافذة واتساب تُفتح لحظة الضغط (داخل حدث المستخدم) حتى لا يحجبها المتصفح، وإن حُجبت يظهر زر **«إعادة إرسال الطلب على واتساب»** في صفحة الإعلان/الطلب.
- الطلب يُحفظ **دائمًا** قبل فتح واتساب، فلا يضيع شيء لو أغلق العميل التطبيق.
- الوظائف في مكان واحد (`lib/whatsapp*.ts`): `generateOrderWhatsAppMessage` · `generateListingWhatsAppMessage` · `generateInquiryMessage` · `generateCustomerMessage` · `createOwnerOrderLink` · `createOwnerListingLink` · `createOwnerContactLink` · `openOwnerWhatsApp` · `openCustomerWhatsApp`.

### إرسال تلقائي من الخادم (اختياري)

لو ضبطت `KK_WHATSAPP_TOKEN` و`KK_WHATSAPP_PHONE_ID` (WhatsApp Cloud API) يرسل الخادم نسخة من نفس الرسالة لرقم المالك مباشرة عبر `lib/whatsapp-send.ts` — فيصل الطلب حتى لو لم يُكمل العميل فتح واتساب. بدونهما يعمل النظام بالكامل عبر `wa.me`.

## الإنتاج

1. شغّل التطبيق على Node 22.13+ مع **قرص دائم** واضبط `KK_DB_PATH` على مساره. لا تعتمد على `/tmp` في Vercel لحفظ بيانات العملاء.
2. `DEMO_MODE = false` من الإعدادات (إخفاء البيانات التجريبية).
3. اختر سياسة النشر: **نشر فوري** أو **النشر بعد موافقة الإدارة** (`REQUIRE_APPROVAL`).
4. عدّل رقم المالك من الإعدادات إن لزم.
5. اضبط `NEXT_PUBLIC_SITE_URL` على دومين الموقع (لروابط المنتجات في رسائل واتساب).
6. راقب `GET /api/health`؛ يجب أن يعيد `200` و`database: "ready"`. القيمة `storage: "vercel-temporary"` تعني أن الموقع يعمل بقاعدة مؤقتة لا تصلح لحفظ بيانات الإنتاج.
7. لا توجد أي مفاتيح سرية في الواجهة — كل البيانات في الخادم وقاعدة البيانات.
